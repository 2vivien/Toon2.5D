# Toon2.5D V1

V1 is the first release contract for the engine: a reusable avatar runtime that can be embedded in web applications and driven entirely through stable semantic APIs.

## V1 release scope

### Runtime
- deterministic lifecycle: create, load, update, render, resize, pause, resume, destroy;
- stale asynchronous load protection;
- explicit renderer ownership and disposal.

### Character
- 52 semantic facial parameters;
- emotion, lip-sync, blink and LookAt composition;
- persistent face overrides;
- slot-based customization with GLB and texture assets.

### Animation
- deterministic keyframe clips;
- state machine with triggers, parameters and conditions;
- transition callbacks;
- crossfade and weighted multi-clip playback;
- runtime-driven animation advancement.

### Rendering
- Three.js WebGL renderer with context-loss recovery;\n- WebGPU renderer with the same core Renderer contract;
- orthographic and perspective cameras;
- constrained damped quaternion LookAt for head and eyes;
- semantic morph-target binding;
- shared renderer/context coordination;
- quality tiers and visibility/FPS adaptation.

### Tooling
- React adapter;
- interactive Studio preview;
- reproducible reference GLB pipeline;
- strict TypeScript;
- unit/integration tests;
- browser release gates, native GLB animation access and deterministic animation event timelines.

## V1 release gates

Every release candidate must pass:

1. workspace build;
2. strict typecheck;
3. unit/integration test suite;
4. reference asset generation and validation;
5. browser Studio smoke tests;
6. browser frame-budget gate;
7. GPU timer gate when WebGL2 timer queries are available;
8. repository documentation consistency.

GPU timing is treated as an additional signal, not as a universal hardware-independent threshold. Unsupported timer-query environments must report the gate as skipped rather than fabricate a measurement.

## Explicit V1 boundaries

V1 does not promise:
- identical performance across physical GPUs;
- full humanoid skeletal IK;
- arbitrary material-graph authoring;
- a complete DCC replacement;
- server-side WebGL rendering.

Those capabilities can be added without changing the semantic runtime contract.

## Release discipline

V1 changes are developed in focused commits, validated in CI, and merged only after the release gates pass.
